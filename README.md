# 串珠文字图纸生成工具

上传串珠帘图纸，自动识别网格与配色，逐列输出穿珠顺序与用量——
把图片图纸变成能照着穿的**文字图纸**。

**图片全程在浏览器里处理，不会上传到任何服务器。** 页面没有后端接口，
线上和本地都用 `connect-src 'none'` 的 CSP 把网络请求彻底关掉。

---

## 输出内容

对应原始需求，生成的文字图纸包含三部分：

1. **每列穿珠顺序** — 从下往上，连续同色合并计数
   `**第1列**：43个黑，6个白，27个黑，5个白，22个黑`
2. **每列各色用量** — 每列每种颜色各用几颗
3. **全图各色总计** — 整张图每种颜色的总数 + 合计颗数

支持以下导出方式：

| 按钮 | 产物 |
| --- | --- |
| 复制 | 剪贴板文本 |
| 下载 文字图纸.txt | 纯文本 |
| 下载 文字图纸.md | Markdown（列号带粗体） |
| 导出 CSV | 整张网格的颜色名矩阵，可贴进 Excel 核对 |
| 导出识别图 | 识别结果的 PNG，用来和原图比对 |

识别结果中如有格子判断错误，可单击选择一格，按住 Shift、Ctrl 或 ⌘ 点击追加多选，
再次点击已选中的格子可取消单格，再从色卡中批量指定正确颜色；色卡用量、
文字图纸和导出文件会立即同步。切到「原图 + 网格」后，还可水平或垂直移动红色网格，
让格线与原图精确对齐。

## 本地调试

需要 Node 18+（只用内置模块，**没有任何依赖**，不用 `npm install`）。

```bash
npm run dev          # http://localhost:5173
npm run dev -- 8080  # 换端口
```

然后打开 <http://localhost:5173>。

> **不要直接双击 `index.html`。** `file://` 下 canvas 读取本地图片会触发跨域
> 污染，`getImageData()` 会抛 SecurityError。必须走 HTTP。

调试用的小工具：

- `http://localhost:5173/?demo` — 直接载入示例图纸
- `http://localhost:5173/?demo&view=raw` — 载入后直接切到「原图 + 网格」校验视图
- 控制台里 `__bead` 是全局状态对象（`cols` / `rows` / `geom` / `palette` / `cells`）
- 开发服务器发的响应头和 `vercel.json` 完全一致（含 CSP），本地看到的行为就是线上行为
- `Cache-Control: no-store`，改完文件刷新即可，不用清缓存

## 部署到 Vercel

纯静态站点，没有构建步骤，也不需要装 Vercel CLI。

**1 · 推到 GitHub**

在 GitHub 新建一个**空**仓库（别勾 README / .gitignore / license），然后：

```bash
cd bead-text-chart
git init -b main
git add -A
git commit -m "串珠文字图纸生成工具"
git remote add origin https://github.com/<你的用户名>/bead-text-chart.git
git push -u origin main
```

**2 · 在 Vercel 导入**

打开 <https://vercel.com/new> → 选 GitHub → 找到这个仓库 → Import，
设置全部保持默认即可：

| 项 | 值 |
| --- | --- |
| Framework Preset | Other |
| Root Directory | `./` |
| Build Command | 留空 |
| Output Directory | 留空 |
| Install Command | 留空 |

点 Deploy，约半分钟后拿到 `https://bead-text-chart.vercel.app`。

`package.json` 里刻意没有 `build` 脚本，Vercel 会当成静态站点直接发布仓库根目录。
`vercel.json` 只负责响应头（CSP、`nosniff`、缓存策略）。

**3 · 之后要改**

改完直接 `git push`，Vercel 自动重新部署，不用再点任何东西。

## 工作原理

**1. 找网格**

先按列（行）求 RGB 均值，再做一阶差分。一格之内整列的颜色构成相同，所以
列均值在格内是常数，只在格线处跳变，差分后就是干净的周期脉冲。
逐像素求差再累加的做法会把 JPEG 噪声一起累积，信噪比差很多。

然后把能量按候选周期折叠，看峰比均值高多少。折叠对相位漂移极其敏感——
候选周期偏差 Δp 在 n 个采样点上会累积 `Δp·n/p` 的漂移，超过 1px 峰就糊了。
所以先在 30 个周期的短窗口上等比粗扫，再在全信号上细扫。真实周期的整数倍
同样得高分，因此在高分区间里取最小的周期。

相位（格线位置）取「超出均值部分」的圆形质心，比 argmax 更接近线的中心。
由相位反推格子起点，第一格允许是负起点（被切掉一角）。

**2. 取色**

每格只看中央 40% 的区域，把颜色粗量化成 4096 桶后取出现最多的一桶的均值。
格线、抗锯齿边缘和 JPEG 杂色都不会把结果拉偏。

**3. 聚类**

在 CIE Lab 空间做贪心选心 + 两轮 Lloyd 迭代，滑杆的量纲就是 ΔE
（约 2.3 是肉眼可辨阈值）。图案边缘的过渡格常被单独当成一种颜色，
所以默认把少于 3 颗的簇并进最接近的颜色。

示例图纸（2157 × 1645）识别为 135 列 × 103 行、每格 16.0 px，耗时约 130 ms；
逐格结果与原图对应像素 100% 一致。

## 识别不准怎么办

| 现象 | 处理 |
| --- | --- |
| 行列数不对 | 切到「原图 + 网格」，红线应当压在图纸自己的格线上；用 ± 微调行列数 |
| 网格和原图没有对齐 | 切到「原图 + 网格」，调整水平、垂直偏移，让红线压在图纸格线上 |
| 颜色种类比实际珠子多 | 把「相近色合并强度」往右拖；或勾选「固定颜色数量」直接填珠子色数 |
| 某两种颜色应该是同一种珠子 | 在色卡里勾选它们，点「合并所选」；点返回箭头可逐次撤销合并 |
| 边缘出现只有几颗的杂色 | 调大「并入少于 N 颗的杂色」 |
| 色名不顺口 | 直接在色卡里改，文字图纸实时更新；调阈值后名字会按颜色就近保留 |

穿珠方向按习惯在「输出选项」里切换：列可以从右往左编号，每列可以从上往下读。
