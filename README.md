# 串珠文字图纸生成工具

上传串珠帘图纸，自动识别网格与配色，逐列输出穿珠顺序与用量——
把图片图纸变成能照着穿的**文字图纸**。

**图片全程在浏览器里处理，不会上传到任何服务器。** 页面没有后端接口，
线上和本地都用 `connect-src 'none'` 的 CSP 把网络请求彻底关掉。

---

## 图片转像素图

「像素尺寸」中的「格子大小（mm）」用于计算实际成品尺寸：宽度 = 列数 × 格子大小，高度 = 行数 × 格子大小。支持小数，默认留空，填写后记住该尺寸；它不改变图像像素或改色结果。原图分辨率仍以 px 显示。

在「处理模式」选择「图片 → 像素图」，上传普通照片、插画或透明 PNG 即可生成
像素图。图片仍全部在浏览器本地处理。

同一张图片的两种处理模式分别保留编辑进度。切回模式时恢复尺寸、配色参数、颜色合并、命名、逐格改色和预览缩放；首次进入另一模式才重新生成结果。重新上传图片会清空两种模式的进度，刷新页面不会保留这些编辑记录。

- 默认 52 列，行数按原图宽高比四舍五入计算（最少 1 行、最多 600 行），可调整为 1–600 行 / 列；默认保持原图比例，取消勾选后可分别设置。
- 「画面效果」提供两种选择：「柔和清晰」（默认）保留自然过渡和细线；「线条鲜明」让色块分界更清楚、线条更突出。
- 「柔和清晰」可调整线条清晰度，默认 65；数值越小越柔和，越大细线越鲜明。两种效果均将透明部分合成到白底；相近色合并、固定色数、色卡及逐格改色仍可使用。
- 「线条鲜明」在长边 2400 的分析预缩放中关闭平滑，减少预缩放混色；显示与 PNG 均按纯色色块输出。小于一格的细节仍可能丢失，增加行列数可保留更多细节。
- 像素图流程为「低分辨率网格取样 → 原色聚类 → 色卡匹配」。先合并原图中相近的颜色，再将代表色按 Lab 最近色匹配到 MARD，减少纸张纹理跨过色卡匹配边界后被放大成杂色；自由配色保留聚类代表色。
- 像素图始终进行颜色聚类，无需单独开启；画面效果位于独立板块。合并强度和固定色数作用于取样后的原色；预览统计显示最终用色数。图纸识别保持原有流程。
- 「预览显示网格」可辅助改色；文字图纸、Excel 和珠子用量会同步生成。
- 「下载像素图.png」按用途导出 PNG：「分享与查看」默认标准长边约 2400px，可选高清约 4800px，按整格倍数放大；「实际尺寸打印」沿用已填写的每格毫米尺寸，可在导出窗口调整，固定 300 DPI 并写入 PNG 打印分辨率。两种用途默认含网格，可取消，也可标注色号（自由配色为名称）。分享图四周添加双向行列编号，默认附底部色卡（按用量降序，显示色号／名称和实际颗数，可取消）；可选添加自定义文字的半透明斜排水印。打印不添加分享图的编号外框、色卡或水印。单边最多 8192px、总计最多 3200 万像素，分享图的编号边框与色卡也计入上限，必要时降低整格放大倍数。导出不含选区，不改变图案编辑结果；不提供分页。「导出当前预览」按当前显示大小保存预览。
- 切换处理模式分别保留已有编辑进度；图片模式中的「重置像素尺寸」恢复 52 列，行数按原图比例计算。

### 色号库说明

「配色色号库」默认选用 **MARD 221 色（公开参考）**，也可选择 MARD 291 色或自由配色。界面仅提供这三项，不再提供色库导入或模板下载。
MARD 数据来自 [HansBug/pindou-color-data](https://github.com/HansBug/pindou-color-data)，
采用 MIT 许可，详见 [数据来源](data/MARD-SOURCES.md) 和 [许可](data/MARD-LICENSE.txt)。
221 核对版与 291 源码版的部分共有色号存在色值差异，请按手中套装选择；选择色库时只显示色号，备料以色号为准。
特殊色按 RGB 近似显示，不能模拟透明、荧光等材质。所有内置数据随本地脚本加载，无在线请求。
所选设置保存在当前浏览器，不上传服务器。更换库会清除手动合并、命名和改色。旧版通用库或导入库设置会回到默认 MARD 221 色。
像素图先聚类原采样、再匹配色卡；图纸识别仍直接聚类原采样。聚类及手动合并后的代表色按 Lab 色差匹配回库内最近色号，相同色号自动合并计数；
固定色数是自动生成结果的颜色上限，色库匹配后可能更少；手动改色主动添加的色号不受该上限约束。
逐格改色可选择库内全部色号，包括尚未使用的颜色。色卡、格子提示、改色与交错配色选项、文字图纸及 Excel 统一只显示色号；自由配色时以可编辑的颜色名称作为标识。
PNG 使用库中原始 RGB，不会再把库内颜色混成新颜色。屏幕显示颜色仅供配色参考。

### 细线保留的依据与限制

研究参考：[Kopf 等，Content-Adaptive Image Downscaling](https://johanneskopf.de/publications/downscaling/)。
本工具采用局部结构判断的轻量实现，不是论文 EM 优化的完整复现，也不使用其他 App 的色板。

每格聚合相近颜色的空间矩，寻找占比 4%–40%、覆盖足够跨度的狭长候选；候选颜色需与主体色有明显差异。
再检查法向两侧是否回到背景色、切向邻域是否存在相近颜色，过滤孤立点和大色块边沿。
相邻格跨着同一条线时沿法向抑制重复选择，降低线宽翻倍的风险。「线条鲜明」直接选择原图线条像素；「柔和清晰」按清晰度在线条原色与该格区域平均色之间插值，其余格不改变。不加黑、不降低全局亮度；亮线也适用。

细线连续性在取样阶段处理：短线段必须在原图中存在，并由两侧颜色、方向一致的可靠线段支持；不跨空白补线，不递归传播，两侧已经相邻连通时不补格，以免加粗斜线。
已移除独立的「保护轮廓线和细线」开关及聚类后补回颜色的过程。旧设置中的该字段忽略，合并后的色数不会因保护功能回升。

平衡插值在聚类和色卡匹配之前完成，只执行一次后续配色流程。色库是离散的，聚类还会合并相近色，因此滑块的相邻数值可能产生相同结果。

取样后先聚类，再按用户选择的 MARD 色库匹配。过强的聚类或过低的固定色数仍可能合并未识别的细线色，
因此不能保证所有细线都保留。照片纹理复杂时可选择「柔和清晰」并降低线条清晰度；重要线条可增加行列数，或在结果中逐格修正。

## 输出内容

对应原始需求，生成的文字图纸包含三部分：

1. **每列穿珠顺序** — 从下往上，连续同色合并计数
   `**第1列**：43个黑，6个白，27个黑，5个白，22个黑`
2. **每列各色用量** — 每列每种颜色各用几颗
3. **全图各色总计** — 整张图每种颜色的总数 + 合计颗数

支持以下导出方式：

| 按钮 | 产物 |
| --- | --- |
| 下载 文字图纸.txt | 纯文本 |
| 导出 Excel | 下载彩色图纸.xlsx，每格填充实际颜色并显示色号／名称；冻结行列编号，附色卡、HEX 和实际用量表。两种模式均支持，纯本地生成 |
| 导出识别图 | 识别结果的 PNG，用来和原图比对 |

在「色卡」中点击「逐格改色」，打开独立编辑窗口，图像默认显示淡网格。
画布左下角提供固定 180×180px 的原图参考窗：以适合窗口时的完整原图为基准，随画布同比例缩放，并跟随当前查看区域移动；点击「适合窗口」恢复完整原图参考。
先用顶部「涂抹选格」选择处理范围，可调笔刷大小；选多了用「擦除选区」去掉，也可取消全选。选好后可改颜色或交错配色。双指移动或空格 + 鼠标左键可拖动画布；普通滚动用于查看，捏合或 Ctrl/⌘ + 滚轮用于缩放。取消全选位于顶部笔刷后方。
直接改色和交错配色共用同一选区。颜色框旁的吸色按钮可从图中取色并立即修改已选格子，不改变选区。
从下拉框选择颜色后立即修改已选格子；「复原」恢复全部手动改色，不受选区影响，「撤销上次更改」撤销最近一次改色（包括吸色和复原）。
选好格子后，可直接改颜色，或在「交错配色」选择／吸取底色与叠加色，再预览，无需另画处理区域。两种操作后都保留选区。原图每格的颜色用于估计两色占比；滑杆 0 为自动，向左调淡、向右调浓。预览只显示在编辑画布中，点击「应用交错配色」写入图纸；预览期间点击「完成」也会应用并保存。取消预览会丢弃预览，不改变已应用的改色。双色与范围均由用户指定，工具不会自动识别脸颊或避开五官。

点击「完成」保存；点击「取消」或按 Esc 还原打开窗口前的状态，保留之前已保存的改色。
色卡用量、文字图纸和导出文件随改色同步；编辑窗口的网格和缩放不影响主图设置。
切到「原图 + 网格」后，还可水平或垂直移动红色网格，让格线与原图精确对齐。

## 本地调试

需要 Node 18+（只用内置模块，**没有任何依赖**，不用 `npm install`）。

```bash
npm run dev          # http://localhost:5173
npm run dev -- 8080  # 换端口
```

然后打开 <http://localhost:5173>。

> **不要直接双击 `index.html`。** `file://` 下 canvas 读取本地图片会触发跨域
> 污染，`getImageData()` 会抛 SecurityError。必须走 HTTP。

调试用的小工具：

- `http://localhost:5173/?view=raw` — 上传图片后切到原图视图
- 控制台里 `__bead` 是全局状态对象（`cols` / `rows` / `geom` / `palette` / `cells`）
- 开发服务器发的响应头和 `vercel.json` 完全一致（含 CSP），本地看到的行为就是线上行为
- `Cache-Control: no-store`，改完文件刷新即可，不用清缓存

## 部署到 Vercel

纯静态站点，没有构建步骤，也不需要装 Vercel CLI。

**1 · 推到 GitHub**

在 GitHub 新建一个**空**仓库（别勾 README / .gitignore / license），然后：

```bash
cd bead-text-chart
git init -b main
git add -A
git commit -m "串珠文字图纸生成工具"
git remote add origin https://github.com/<你的用户名>/bead-text-chart.git
git push -u origin main
```

**2 · 在 Vercel 导入**

打开 <https://vercel.com/new> → 选 GitHub → 找到这个仓库 → Import，
设置全部保持默认即可：

| 项 | 值 |
| --- | --- |
| Framework Preset | Other |
| Root Directory | `./` |
| Build Command | 留空 |
| Output Directory | 留空 |
| Install Command | 留空 |

点 Deploy，约半分钟后拿到 `https://bead-text-chart.vercel.app`。

`package.json` 里刻意没有 `build` 脚本，Vercel 会当成静态站点直接发布仓库根目录。
`vercel.json` 只负责响应头（CSP、`nosniff`、缓存策略）。

**3 · 之后要改**

改完直接 `git push`，Vercel 自动重新部署，不用再点任何东西。

## 工作原理

**1. 找网格**

先按列（行）求 RGB 均值，再做一阶差分。一格之内整列的颜色构成相同，所以
列均值在格内是常数，只在格线处跳变，差分后就是干净的周期脉冲。
逐像素求差再累加的做法会把 JPEG 噪声一起累积，信噪比差很多。

然后把能量按候选周期折叠，看峰比均值高多少。折叠对相位漂移极其敏感——
候选周期偏差 Δp 在 n 个采样点上会累积 `Δp·n/p` 的漂移，超过 1px 峰就糊了。
所以先在 30 个周期的短窗口上等比粗扫，再在全信号上细扫。真实周期的整数倍
同样得高分，因此在高分区间里取最小的周期。

相位（格线位置）取「超出均值部分」的圆形质心，比 argmax 更接近线的中心。
由相位反推格子起点，第一格允许是负起点（被切掉一角）。

**2. 取色**

每格只看中央 40% 的区域，把颜色粗量化成 4096 桶后取出现最多的一桶的均值。
格线、抗锯齿边缘和 JPEG 杂色都不会把结果拉偏。

**3. 聚类**

在 CIE Lab 空间做贪心选心 + 两轮 Lloyd 迭代，滑杆的量纲就是 ΔE。
不再按颜色用量自动清理少量颜色，避免吞掉小细节；需要减色时，可在色卡中选择合并。

示例图纸（2157 × 1645）识别为 135 列 × 103 行、每格 16.0 px，耗时约 130 ms；
逐格结果与原图对应像素 100% 一致。

## 识别不准怎么办

| 现象 | 处理 |
| --- | --- |
| 行列数不对 | 切到「原图 + 网格」，红线应当压在图纸自己的格线上；用 ± 微调行列数 |
| 网格和原图没有对齐 | 切到「原图 + 网格」，调整水平、垂直偏移，让红线压在图纸格线上 |
| 颜色种类比实际珠子多 | 把「相近色合并强度」往右拖；或勾选「固定颜色数量」直接填珠子色数 |
| 某两种颜色应该是同一种珠子 | 在色卡里勾选它们，点「合并所选」；点返回箭头可逐次撤销合并 |
| 边缘出现只有几颗的杂色 | 在色卡中查看对应位置，再选择需要合并的颜色 |
| 色名不顺口 | 直接在色卡里改，文字图纸实时更新；调阈值后名字会按颜色就近保留 |

在「输出选项」选择按行或按列：按行时设置行编号方向（上到下／下到上）和每行串珠顺序（左到右／右到左）；按列时设置列编号方向（左到右／右到左）和每列串珠顺序（上到下／下到上）。方向设置合并使用，行列号固定为 Markdown 粗体，无需勾选。分行／分列用量随输出方式切换。
